## 构造测试数据的思路

- 正常数据使用校园卡、雨伞、耳机等原型示例。
- 边界数据覆盖最短和最大长度。
- 异常数据覆盖空值、错误类型、未来时间、控制字符和损坏 JSON。
- 权限数据使用 `seed-user-1` 与本地用户，验证只能修改自己的信息。
- 状态数据覆盖 `open/resolved` 与 `lost/found` 的四种组合。
- 云接口使用 fake `callFunction`，验证请求结构和错误转换。

## 将来测试人员的刁难点

- 发布空表单或只输入空格。
- 发生时间选择未来。
- 切换招领状态，确认显示“已归还”而不是“已找回”。
- 连续编辑、删除和重启 APP，确认数据一致。
- 导入格式错误或包含大量无效条目的 JSON。
- 断开网络后使用本地数据，验证核心流程不依赖阿里云。

## 手工验收

Release APK 已在实体安卓设备执行：

1. 浏览首页并切换全部/寻物/招领。
2. 从首页进入校园卡详情。
3. 点击显示联系方式并复制。
4. 空表单发布时逐项显示校验错误。
5. 发布一条寻物信息并进入发布成功页。
6. 发布一条招领信息并进入发布成功页。
7. 点击取消发布返回首页，应用进程保持运行。
8. 在“我的发布”标记已找回，确认状态同步为“已找回”。
9. 删除测试信息并确认列表同步。
